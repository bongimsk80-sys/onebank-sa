# OneView — handoff for Claude Code

Last updated 19 Nov 2026. Read this before changing anything. It carries the decisions and state from the planning and rebuild work done in Claude (claude.ai), which Claude Code cannot see.

## 1. What OneView is

A governance-first treasury console for South African mid-market companies (51–200+ staff) that bank with two or more banks. It shows consolidated balances and transactions across FNB, Standard Bank, Absa, Nedbank, Capitec and Investec, and routes every payment through one maker-checker approval policy with a tamper-evident audit trail.

It is modelled on SingleView (Saudi Arabia) but deliberately **not** a copy: South Africa has no open-banking mandate, so the value is approval control and audit, not data access.

## 2. Decisions already made (do not reopen without the owner)

- **Name is OneView.** Section 22(5) of the Banks Act bars an unregistered business from using "bank" in its name; CIPC lists "Bank" as a restricted word. Never reintroduce "OneBank" in user-facing text. Still to do by the owner: CIPC name search and trademark search ("OneView" is also an HPE product name).
- **Bank data comes through Stitch, not statement uploads.** Stitch documents a Financial Data product (OAuth 2.0 + PKCE, GraphQL; accounts, balances, up to 3 months of transactions). Open questions for Stitch, to be answered in writing before go-live: is Financial Data open to new clients and business accounts at all six banks; bank API vs credential-based access and who carries liability; pricing.
- **Yodlee stays switched off** (`YODLEE_ENABLED=false`). No current South African coverage found; its past SA access (22seven) used customer banking credentials, which SA banks say breaches their terms. Enable only after Yodlee confirms SA business-banking coverage in writing.
- **No money moves.** Payments are simulated during the beta. Direct payment execution needs a written legal opinion plus SARB authorisation or a licensed sponsor under the activity-based Authorisation Framework. Do not build live execution without the owner confirming both.
- **Honesty rules for any public text:** label every feature Live in beta / In integration / In development / Planned; never present simulated payments as GMV, volume or traction; no testimonials unless named and consented; no unverifiable competitor claims.
- **Primary customer** is the financial controller or CFO of a medium firm. Proposed pricing in the investment thesis (R1,950 / R4,500 / from R12,000 a month) differs from the site (R799 / R2,499); the owner has not chosen yet.

## 5. How the app is built

- **Tenant isolation:** every API route calls `resolveOrgId` and returns 403 when the user has no organisation. Never reintroduce `orgId ? { organisationId: orgId } : {}` — that pattern leaked every tenant's data.
- **Bank connectors:** `lib/connectors/types.ts` defines `BankConnector`; providers in `stitch.ts`, `yodlee.ts`, `simulated.ts`; `sync.ts` is the only caller (token refresh, account upsert, transaction dedupe hash, audit entry). Add providers there, never in pages or routes. Routes: `app/api/connections/*`, Stitch callback at `/api/connections/stitch/callback`.
- **Two-factor:** TOTP via `otplib`; `requireMfa(session)` in `lib/api-auth.ts` gates every privileged mutation for admin, approver and executor.
- **Secrets:** `lib/secure-crypto.ts` (AES-256-GCM, key from `ENCRYPTION_KEY`) for bank tokens and MFA secrets.
- **Audit:** `ActivityLog` is append-only and hash-chained per organisation by the Prisma extension in `lib/prisma.ts`; verify with `lib/audit.ts` / `GET /api/activity-log/verify`. Never update or delete audit rows.
- **Website enquiries:** `POST /api/enquiries` (origin allow-list, consent required, honeypot, throttle).
- **Migrations:** always add a migration with `prisma migrate dev` / `migrate diff`; never `db push` against production. `vercel-build` runs `prisma migrate deploy` on production builds only.

## 6. Checks before any pull request

```bash
npx tsc --noEmit        # must pass
npm test                # Stitch connector contract test
npm run build           # needs DATABASE_URL, DATABASE_URL_UNPOOLED, AUTH_SECRET, ENCRYPTION_KEY in .env.local
```

For database changes, build a fresh local Postgres from migrations and confirm `prisma migrate diff --from-migrations prisma/migrations --to-schema-datamodel prisma/schema.prisma --exit-code` reports no drift. Work on a branch and open a PR; pushing to `main` deploys production.
